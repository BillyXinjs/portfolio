Fashion Trend Daily

HTML brief · auto-pushed weekly
Scrapes runway coverage and distills trends along three axes — silhouette, colour, fabric — then pushes a brief on a schedule.
Show prompt
Fetch the last 7 days of runway coverage from the Big Four fashion weeks (Milan / Paris / New York / London), focused on Spring/Summer 2026 womenswear, and build a trend brief:
1. Top 5 silhouettes (with visual reference: A-line / tailoring / deconstructed / oversize / utility)
2. Top 5 colours (with Pantone codes + estimated peak month)
3. Top 3 fabrics (with finishing keywords, e.g. pleating, bonded seams, brushed)

Competitor & Reputation Comparison

Comparison matrix · P0–P2 risk register · response plan
Two search passes — a reputation baseline, then competitor and controversy angles — producing a scored matrix, risk register and response plan.
Show prompt
Two objectives:
Competitive read — where our brand stands against competitors in word of mouth and what users actually compare.
Reputation monitoring — true sentiment health, positive/negative distribution, and negative risk points, with warnings and a response plan.

Search strategy (two passes)
Pass 1: search the brand (including name variants), sort by hottest, exclude official accounts, pure ad copy and image-only posts; keep the top 5 notes with genuine discussion (reputation baseline).
Pass 2 (two directions, 2–3 notes each):
  competitive angle — "brand vs brand", "is competitor X worth buying";
  controversy angle — "complaints", "quality", "sizing", "colour mismatch", "pilling/shrinkage", "after-sales".
Merge with pass 1 and settle on the 10 most information-dense notes.

Extraction rules
For each note, pull comments with 5+ likes, prioritising questions, brand comparisons and negative disputes. Tag every comment with:
- category (brand comparison / quality doubt / price-value / fit / colour mismatch / after-sales / recommendation / link request)
- sentiment (positive / neutral / negative)
- competitor names mentioned

Analysis output
- Sentiment volume and distribution, plus an overall health verdict
- Competitive matrix scored across reputation, quality, price, design, fit, expertise, after-sales — one-line strength, one-line weakness
- Top 5 user pain points by frequency
- Top 5 positive and top 5 negative keywords, listed separately
- Negative risk register graded P0/P1/P2 by severity and reach, with note links and like counts
- Trend judgement and response plan: PR holding line, service-script fixes, QC improvements, competitive plays, monitoring priorities

Product Copy

Mobile detail page HTML · copy deck
Structured parameters plus a product image produce a mobile detail-page demo and copy, cutting launch copy time sharply.
Show prompt
[Product]
- Brand / product name / price / strikethrough price
- Target customer (e.g. urban professional women 30+)
- Price tier (mid / premium / luxury)
- Fabric composition (write "per care label" if unknown)
- Size chart (height/weight range for S/M/L)
[Visual]
- Primary colour / tone (e.g. understated luxury / minimal / youthful)
[Structure — 9 modules top to bottom]
1 brand bar · 2 hero image with season badge · 3 price block with hook line and 3–4 selling-point tags · 4 four numbered selling points with plain-language explanations · 5 fabric and construction detail · 6 size table with a fit note · 7 three styling scenarios · 8 care and after-sales · 9 CTA buttons
[Copy rules]
- One-line headline, one-line hook. No adjective stacking.
- Lead each selling point with a short phrase, then explain it in plain words.
- Never invent missing facts — default to neutral phrasing such as "per care label".
[Technical]
- 375px mobile container, centred on a light grey backdrop. Leave unfilled fields as visible placeholders.

Campaign Playbook

Phase-by-phase config sheet · risk register
Splits a promotion into pre-sale, launch, peak and clearance phases, generating discount tiers and stock allocation with risk flags.
Show prompt
Walk the campaign through pre-sale → launch (opening day) → peak (main day) → clearance. For each phase give the time window, core objective, main mechanic and GMV share.

Then generate the mechanic configuration per phase:
- Tiered spend thresholds (4 tiers)
- Member pricing (member discount, points multiplier, stack rules)
- Stock locking (pre-sale allocation, safety水位, oversell threshold)

Stock and settlement checks — 6 stock-side items (lock, oversell, cross-channel, size breaks, release, deposit allocation) and 6 settlement-side items (stacking rules, member-price exclusivity, return allocation, commission, tax, price protection).

High-risk configuration points — red / amber / green grading. Each red flag (stacked discounts producing negative margin, locked stock not released, pre-sale stock unallocated, price protection) must carry a concrete avoidance action.

Live-Commerce Competitive Report

HTML report · Excel workbook · pitch summary
Pulls competitor sell-through and placement data by category through a third-party data API, producing a report usable in pre-sales demos.
Show prompt
Pipeline: data acquisition → processing → report output → asset retention.

[Sources]
1. Primary: query a configured third-party live-commerce data API (key: <YOUR_API_KEY>) for real-time platform data.
2. Local: read cached brand JSON files under /workspace/demo/data/.
3. Hard rule: cross-validate both sources and annotate any definitional gap. Mark missing data explicitly as "to confirm" — never fill by assumption.

[Scope]
Our brand plus two competitors · channel: the short-video commerce platform (live + short video + product cards) · 30-day window primary, 90-day as trend support.

[Dimensions]
1 Category structure — sub-category split, share by value and by units (dual view so price differences don't mislead), SKU count and newness cadence
2 Price bands — distribution across four bands; average, median, main band, high/low; discount rate and basket size; who competes on volume vs price vs positioning
3 Hit products — top 10 by 30-day value and units cross-ranked; hit profile; new hits vs evergreen; whether hits sit in the main price band
4 Competitor profile — audience age and spending power, store matrix, content cadence and creator scale, one-line positioning each

[Processing requirements]
Multi-source integration into one master table · unit and window alignment · dedupe, outlier detection, missing-value flagging · brand × price band × category cross-tab · computed metrics (share, period growth, average price, hit concentration) · charts (comparison bars, band distribution, hit ranking, brand radar).

[Output]
1. One single-file HTML report (cover, summary, contents, four dimensions, comparison charts, conclusions)
2. One Excel workbook with the raw detail by brand (multiple sheets)
3. A conclusion-first verbal summary ready for a pre-sales pitch

[Quality bar]
Demo data must be traceable. Anything unconfirmed is flagged "to confirm". Conclusion first, tables clear, material differences highlighted. Explain non-obvious financial or data terms in plain language.

Business Analytics

2 scenarios

Multi-Source Table Merge

Health-check report · master-data dictionary · wide table
Definitions rarely match across systems, so it runs a data health check and lists every discrepancy before building one wide table — alignment drops from days to a single conversation.
Show prompt
These tables come from different systems.
First, run a data health check: examine [store name], [date], [category] and [currency unit] across all tables for inconsistent definitions. For each, list the inconsistent field, how each table writes it, and the blast radius. Do not merge yet — give me the health report first.

Then build a store master-data dictionary using these rules:
1. Store names use the official full name (e.g. "Deji" → "Nanjing Deji"; "Marina Bay" → "Singapore Marina Bay")
2. Dates normalised to YYYY-MM-DD
3. The store field is uniformly named [store_name]
Output a store code mapping table (official name / aliases per table / city).

Finally, merge the 5 tables into one store-level operating wide table, one row per store:
store / city / monthly sales / units / online GMV / offline GMV / referral redemptions / members / average gross margin. Online and offline fields must map to the same store. All amounts in yuan.

Weekly Operating Report

Bi-weekly HTML report with charts
Many tables, mixed definitions — so it states metric definitions and reconciliation logic first, then generates the bi-weekly operating report.
Show prompt
Step 1 — Give me a structural overview only, in clear text. Do not change any data; I'll tell you what to adjust.

Step 2 — Generate a bi-weekly operating report as an HTML file:
1. Overview: core metrics (UV, orders, conversion rate, basket size, UV value) and the period definition
2. Week comparison: split the two weeks and compute period-over-period; also use the table's own "vs same period last week" field as a second view
3. Module analysis: homepage traffic, page/floor efficiency, channel structure, campaign effect, associate operations — one or two key conclusions each
4. Charts per section (trend line, share pie, comparison bars), each paired with a "data conclusion" and an "action recommendation"
5. Close with "bi-weekly summary + next week's focus"
Visual: clean business style, restrained accent colour.

Offline Retail

2 scenarios

Inventory Health Alert

HTML report with six chart families
Auto-detects fields, runs ABC classification and days-of-cover, and flags both slow-moving and stock-out risk.
Show prompt
ABC classification — inventory value share = stock × unit price; A = top 70%, B = 70–90%, C = final 10%.
Days of cover — current stock ÷ average daily sales, prefer the last 90 days.
Slow-mover alert — cover above 120 days is flagged slow; stock below safety stock is flagged high stock-out risk.
Multi-dimension rollups — by category, supplier, store and season.
Charts — ABC pie, category distribution, cover histogram, risk scatter, supplier comparison, store health.

Input Excel must contain: SKU code, category, item name, current stock, safety stock, unit cost, retail price, sales in the last 30 (or 90) days, supplier, store.

Output: a complete HTML analysis report — overview, category structure, cover health, stock-out risk, supplier performance, store comparison — written in plain language for business owners.
